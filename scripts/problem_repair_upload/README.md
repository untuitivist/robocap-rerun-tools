# 按问题清单找原件并补传

1. 保留完整工具文件夹，电脑需有 uv、Git/Git LFS，工具 `.env` 中已配置数据集账号。
2. 双击 **`repair_problem_sessions.bat`**，粘贴 Aaron 的 `problematic_sessions.md` 路径；也可以把 Markdown 放到 BAT 旁，直接回车。原件和已经加过箭头状态的版本都支持。
3. 自动搜索本机盘、移动盘、映射盘，并从系统网络记录发现未映射的共享目录，尝试现有 F 盘共享（包括 F$）。额外共享路径不知道就直接回车。只使用当前账号已有权限，不改对方共享、防火墙或账号设置。
4. 等窗口结束，自动打开 `report.html`。结果和 `run.log` 在根目录 `_artifacts/problem_repair_upload/<时间>/`。

**双击默认会补传**：找到有效原件后，只替换清单里仍有问题的对应文件，保留源文件、远端日期和其他文件。上传后校验 SHA-256，并同时更新 manifest 与索引；远端已正常的文件不覆盖。一个文件能补齐时就先补齐，不要求整段所有问题都能解决。

支持缺失/空/损坏的视频、动捕 CSV/TRC/BVH、腕 IMU 和头戴传感器。IMU 必须有实际 ACC/GYRO 数据，视频完整解码，动捕检查实际轨迹；无有效 marker、缺时间戳另做检查。允许有少量缺点的导出用于补齐缺文件，但保留检查警告，**不表示整段质量通过**。

无法找到原件、原件也坏、多个有效副本内容不同、设备 ID 不匹配、时钟/动作配对（G）、量程/饱和（H）会在报告列出，供负责人处理。不补造空 IMU，不猜测补帧，不缩放数值，不自动交换 Session。缺失数据是否永远无法恢复，仍需现场确认。不会解压压缩包；压缩包需先由现场人员解压后再运行。

查看 `results.csv` 的逐问题结果和 `files.csv` 的文件明细；扫描无权限/掉线记录在 `scan_errors.csv`。扫描不完整不能视为所有位置都已检查。中途退出时，已完成结果保存在 `progress.jsonl` 和日志；重跑会先核对远端，不重复覆盖已正常文件。原有全量质量标签保留，未把局部修复冒充为整段验收。不要在其他电脑同时重传同一个 Session。

没有有效本地原件时，不为此重新下载远端大文件，报告会注明“远端待复核”，不能据此认定远端仍坏。清单中已有“已解决”箭头的条目会读回验证，不沿用旧状态直接判通过。

只有元数据、LFS 占位或零字节、没有所需格式的实际原文件时，直接记入缺原件报告，不逐段请求远端。发现可能可用的原文件后，才以最新远端 manifest 核对和补传，缓存元数据不作为上传依据。已下载的远端缓存只有 SHA-256 与本次远端清单相符时才复用。

维护人员可通过 BAT 传参（此方式需显式加 `--apply` 才上传）：

```bat
repair_problem_sessions.bat --report "D:\problematic_sessions.md" --root "F:\." --root "\\SERVER\DATA" --apply --open-report
```

去掉 `--apply`：检查并预览；`--scan-only`：只找目录、不访问远端。`--auto-roots`：额外搜索所有可访问盘。工具不修改原始问题 Markdown、飞书表格或聊天消息。

中断后可加 `--sources-index "上次结果目录\sources.json"` 复用已完成的目录搜索，原文件仍重新检查。新接入的共享盘用 `--root` 加入补搜；旧扫描不可访问项会保留在报告，不代表重新全盘扫描完成。

命令行加 `--discover-shares` 自动发现网络共享。发现和访问失败记录在 `network_discovery.csv`；仅检查系统已知节点，不扫描整个 IP 网段。对方未开共享、网络不可达或账号无权限时仍无法读取 F 盘，可到现场电脑直接双击运行。
