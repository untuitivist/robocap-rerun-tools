# 完整检查：双击 BAT

**双击 `inspect_sessions.bat`**，原始数据在 `F:\` 就回车，共享目录没有就回车。
然后选择动捕帧率：240 FPS 填 `8`（默认），120 FPS 填 `4`。不用手动输命令。
请保留完整工具文件夹并预装 uv。运行会完整读取数据和解码视频，需要比以前更久；等待窗口显示结束即可。

检查内容：

- 每个 Segment 的六路头戴视频、头戴 IMU/MAG、左右腕视频和 IMU/MAG 是否齐全。
- 动捕目录唯一，并有第三人称视频。主人体 **Body0 的 TRC、BVH、CSV 三种都必需**；帽子 **Tracker0 的 TRC、CSV 都必需**。
- Body1/2/3 等是额外追踪对象，出现时逐个检查 TRC、BVH、CSV。HH 不设置额外人体数量的硬规则，按实际文件和动作配置检查。
- 每个物品分别检查 TRC、CSV，例如 BigBox0 和 BigBox1 分开检查，不要求物品或帽子有 BVH。文件名可带录制前缀；不同录制、不同编号不能互相补齐格式。
- 视频能否完整解码且有画面帧；数据库能否读取、表和字段是否存在、是否有实际有效记录。
- TRC/CSV/XRS/BVH/C3D 是否有实际轨迹数据；支持的文本格式会核对列数、实际行数与表头，区分截断、空数据、部分缺点。
- 原有帧数关系、时间戳与丢帧分析仍保留。原始录制不要求提前存在发布清单；已下载副本可用 `--layout published` 额外要求清单和检查报告。

要判断是否**整个物品都漏导出**，由准备工具的人填写同目录的 `mocap_requirements.csv`，其他人照常双击 BAT。表头为：

```csv
action_id,additional_bodies,objects
```

每个动作一行：第一列动作编号；第二列额外必需人体（如 `Body1;Body2`）；第三列必需物品（如 `BigBox0;BigBox1;ArmlessChair`）。多个名称用英文分号分隔，编号必须逐个填写，大小写不敏感。
只有确认无额外人体/物品时才留空对应单元格。Body0 和 Tracker0 始终必需；包括 HH 在内，额外人体只按实际导出或这里的配置检查。
目前清单仅含表头，未推测实际物品名称；未配置的动作明确显示“动作刚体清单待确认”，不会判定物品齐全。
检查也会利用发现的 MARS 定义/TRB/XRB 名称提示缺少的导出文件，但这些文件本身不能替代 TRC/BVH/CSV。
需要使用其他清单时，BAT 或 `inspect` 命令可传 `--mocap-requirements <清单路径>`。

结束后自动打开汇总表。结果在 `_artifacts/session_inspection/<运行时间>/`：

- `report.html`：先看问题汇总，再点开每个 Session 的完整报告。
- `sessions.csv` / `issues.csv`：录制汇总 / 具体问题。
- `run.log` / `scan_errors.csv`：运行日志 / 扫描未完成的位置；各 Session 还有视频解码日志。

“文件检查通过”不等于时间戳、同步或动作质量通过，请同时看报告原有的帧数和时间戳部分。
发现问题只报告，不删除、不修补、不上传。正在录制、有数据库未合并日志、无法识别的格式都会明确提示，不会算作通过。
三项退出码：0 为文件检查通过，1 为有问题或扫描不完整，2 为参数或环境问题。

要检查后批量补传：双击项目根目录 `start_web.bat`，在“统计”页选择原始数据根目录，点 clean 分批上传。入口会先完整检查本地，再比对远端；本地多出的刚体会补传。勾选“重做全部检查报告”可刷新所有报告。共享盘可换一个根目录再运行。

缺文件、空文件、损坏文件或未能完成关键检查的 Session 暂不进入正常数据集，具体原因在原始根目录的 `_reports/batch_upload_<时间>/report.html` 和 `issues.csv`。`sessions.csv` 记录逐条上传结果，`run.log` 保留完整日志。未配置物品名单单独提示待确认。

补传保留原远端日期目录和远端独有文件，不删除数据。索引 `metadata.jsonl` 和 Session 的 `manifest.json` 新增 `mocap_rigid_names`，例如 `["Body0", "Tracker0", "BigBox0"]`，只记录实际文件中的名称。
