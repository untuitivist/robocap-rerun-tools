# 动捕重新导出（双击 BAT）

默认沿用你提供的现场报告 `20261022_213918_248704` 中的问题与录制身份，只处理动捕相关的 74 个 Session（84 个问题项），不处理腕部 IMU/视频。每次运行都会重新发现现场目录，旧的源和目标路径只作为搜索范围线索与历史对照。

1. 双击 `01_find_batches.bat`：刷新已知 NOKOV 和原始 Session 数据根目录，发现新增批次、补齐的目录和此前未映射的录制，再打开最新批次清单。点“复制路径”或“复制全部批次路径”，按报告列出的录制在 NOKOV 中重新导出。
2. 导出结束后，双击 `02_copy_reexports.bat`：再次刷新目录映射，再检查实际导出内容，按完整录制名复制回对应 Session。第一步运行后新增加的目录也会纳入，旧路径失效不会被直接沿用。不要在导出进行中运行。

不需要选择报告或填路径。内置历史报告只有 25 个源录制和 20 个原始 Session 路径，这些不是本次发现数量的上限。默认由历史路径提取数据根目录，目前是 `F:\桌面\nokov` 和 `F:\桌面\EgoMocapActionsDataset`，搜索其下所有批次/日期目录；不会默认重新遍历其他盘或发现网络共享。根目录不可访问时记录搜索未完成；数据已移到别处时用 `--root` 指定新的搜索范围。缓存、备份、分段数据和导出文件子树不会作为额外来源反复遍历。

单个目录读取超过 30 秒会跳过并记入 `scan_errors.csv`，等待时每 5 秒显示进度；继续检查其他目录并保存阶段报告。搜索未完成时不会把已找到的一份副本当作唯一结果自动复制；按 Ctrl+C 会保留报告且不继续复制。BAT 仅保留英文启动命令，中文说明由程序显示，避免换行被转换后出现命令解析报错。

报告区分“历史清单未记录/未现场查找”“搜索未完成/尚未确认”和“本次搜索范围内未找到”；后一种也不代表其他盘中不存在原件。HTML 与 `plan.json` 记录搜索根目录、开始/结束时间、是否完成及新旧映射差异。旧路径保存在 `historical_sources`/`historical_destinations`，不与本次结果混合凑成可复制来源。

复制前检查 Body0 的 CSV/TRC/BVH、Tracker0 的 CSV/TRC、原清单及旧目录中已有的动捕文件，以及新发现的额外人体和物品配套导出。内容无效、缺失、名字冲突或多份副本不乱配，报告中会说明。重复嵌套的同名 mocap 目录会合并一层；同名文件内容不同则停止该 Session。

检查兼容本机真实样例中的 NOKOV 格式：CSV/制表文本省略帧号列名时，仍从实际 Timestamp 列读取；不能把递增帧号当作正常时间戳。Body TRC 只有在 `NumMarkers`、基础点名称、`基础点名_编号` 派生名称以及重新从 X1/Y1/Z1 编号的第二组坐标标签全部匹配时，才按基础点数量检查，额外非空坐标仍会拦截。Tracker 的 `RCalc::基础点名` 计算点有实际坐标，必须连同基础点一起检查。两种格式都会保留表头说明，不修改源文件。

真实缺失点、整帧无点、列截断、声明帧数不符、零/缺失/重复/倒序时间戳仍会阻止复制。单个 Session 会汇总可检查文件的错误；时间戳错误显示数量、实际列号及最多五条行号、帧号和原值。成功复制的 `journal.json` 保存逐文件检查结果，`copy_results.csv`/HTML 同时保留冗余表头或计算点说明。格式兼容不代表本次重新导出的文件已经通过，需在持有原件的电脑重新运行第二步。

原始 NOKOV 文件不动。旧动捕目录保存在 Session 同级的 `_artifacts\mocap_reexport_backups\Session名\批次编号\old`，可按其中 `journal.json` 查找；不会删除备份。备份不会被正常数据扫描/上传当成原件。复制不代表问题已解决，尤其 G 类时钟/动作配对仍需人工复核。随后使用已有检查/上传工具，不会在这里自动上传。

报告和日志：工具根目录 `_artifacts\mocap_reexport\运行时间_编号\`。`report.html` 看批次与逐 Session 对照；`batch_paths.txt` 是纯路径；`sessions.csv`、`scan_errors.csv` 查找不到/重复/不可访问；第二步另有 `copy_results.csv`。

维护者可传 `--rescan` 扩展到本地盘及已知共享，或 `--root "D:\数据"`（可重复）明确指定搜索范围；`--scan-timeout 60` 调整超时。第一步支持 `--snapshot-only` 只看内置历史映射、`--inventory "WizTree.csv"` 离线读清单，这两种模式都明确标记未现场查找；第二步不能使用离线映射复制。内置录制名来自身份核对过的 manifest，不按时间猜配，也不宣称历史问题目前仍全部存在。
