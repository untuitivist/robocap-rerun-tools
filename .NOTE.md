# Project Notes

This file records confirmed project intent and separates it from proposals that still require
approval.

## Confirmed Intent

- The project inspects and aligns Robocap, NOKOV motion-capture, third-person video, and optional
  robowrist sensor data, then exports synchronized Rerun recordings.
- Dataset exports keep full session data by default. Video packaging uses compressed video by
  default while preserving timing metadata needed for alignment and inspection.
- Long CLI-backed Web operations must stream combined stdout/stderr into the shared Output box.
  Show elapsed time and parsed `[n/total]`/percentage progress when available, otherwise an animated
  unknown-total bar. Do not set a process timeout. Bound retained logs to 1000 lines or about 256 KiB.
- Every Rerun export uses one sensor layout: `middle_mag` spans the two Robocap IMU rows beside
  left/right ACC and GYRO pairs, followed by one three-column MAG/ACC/GYRO row for each available
  left/right wrist. Missing streams and fully empty sensor sections are omitted. There is no
  separate display-layout option or Blueprint preset.
- Installation is uv-managed. On Windows, the documented entry point is `start_web.bat`; it runs
  `uv sync --extra web`, creates the environment, and installs Python dependencies plus bundled
  `ffmpeg` and `ffprobe`. Users do not install Python/FFmpeg or edit the system `PATH` separately on
  supported Windows x64, Linux x64, and macOS platforms.
- The next distribution target is a ModelScope DatasetHub dataset.
- The dataset hierarchy is action-first: `EgoMotionActions/PXX/<session_id>/`, where `PXX` is the
  action primitive ID from `EgoMocap Actions.xlsx` (`P01` through `P29`), not a participant ID.
- Every session uses `mocap/` as the canonical motion-capture directory name. The top-level local
  collection path may still be named `nokov`; NOKOV remains the vendor/format name, not a session
  child directory name.
- On 2026-08-17, the existing `Z:\DATASETS\Frodobots\nokov` collection was migrated in place:
  15 session-level directories, generated analysis/ModelScope path references, three ZIP archives,
  and three RAR archives now use `mocap/`. The collection root itself remains unchanged.
- The complete published dataset hierarchy and required/optional file definitions belong in the
  generated dataset-root `README.md` Dataset Card. The Web UI must not duplicate that structure.
- The published dataset includes the generated inspection HTML for every session. Each report is a
  self-contained HTML file with its JavaScript embedded, is stored with its corresponding session,
  and is referenced by the session manifest.
- ModelScope access tokens or other credentials must never be written to the repository.
- No dataset is uploaded until the target owner/repository, visibility, license or access policy,
  and source-session scope are explicitly confirmed.

## Confirmed ModelScope Layout

```text
<dataset_root>/
  README.md
  metadata.jsonl
  raw_calibration/
    <device_id>/
  EgoMotionActions/
    PXX/
      <session_id>/
        <session data files>
        timestamp_anomaly_detail_table.html
```

- Each session remains the primary recording/sample unit and is nested under exactly one action
  primitive directory.
- Participant identity, when available, uses a separate metadata field such as `participant_id` or
  `subject_id`; it must not be inferred from the `PXX` action ID.
- The dataset-level `metadata.jsonl` has one row per session and includes at least `primitive_id`,
  `session_id`, the packaged data paths, and `inspection_html`.
- The tool stages direct DatasetHub files under `EgoMotionActions/PXX/<session_id>/` rather than
  publishing only a session ZIP. Re-staging updates matching metadata rows without deleting
  unrelated staged files.
- ModelScope authentication uses `MODELSCOPE_API_TOKEN` in the repository-local, Git-ignored `.env`.
  The Web UI can save, clear, and validate it without displaying or logging the saved value.
- The ModelScope dataset repository is stored as `MODELSCOPE_REPO_ID=owner/name` in the same `.env`.
  Web startup restores it, Web save persists it, and CLI `--repo-id` is only a one-command override.
- The active ModelScope dataset repository is `untuitivist/EgoMotionActions`. Its root `README.md`
  is the rendered Dataset Card and must be uploaded whenever the generated dataset documentation changes.
- The generated Dataset Card includes the complete P01-P29 action task catalog, grouped into the six
  collection categories, plus the global operator rules. Every task records its participant instruction,
  geometry, duration, room configuration, and purpose; episodes per participant remain TBD.
- The generated Dataset Card uses ModelScope's native SDK and Git download components instead of a
  detailed `uv` installation guide, and keeps a direct `metadata.jsonl` parsing example.
- Dataset updates are documented by download method: a Git clone uses `git pull --ff-only` (and
  `git lfs pull` if LFS objects remain missing), while an SDK download is refreshed by rerunning the
  SDK download command with the same local directory.
- The active ModelScope repository reports `Apache License 2.0`; the Dataset Card YAML front matter
  must declare the same license.
- The English `Locomotion Primitives` worksheet and the English task records embedded in
  `egomocap-actions.html` were checked field by field and match for all 29 tasks. The workbook's
  `Sheet1` is the corresponding Chinese table.
- Session staging refreshes an existing generated Dataset Card when the template changes, so a staged
  repository cannot silently retain an obsolete action catalog.
- The staged inspection HTML is rewritten through its embedded JSON payload so uploaded reports use
  the session ID instead of a local absolute session path.
- Uploads use the official `modelscope-hub` client and its resumable cache by default.
- One upload publishes every staged session referenced by `metadata.jsonl`; it never publishes a
  complete metadata index while omitting some of the indexed session directories.
- The Web ModelScope page derives the staging root from the Session directory as its sibling
  `_modelscope_dataset`; users do not enter the same path twice.
- Calibration data is stored once under dataset-level `raw_calibration/<device_id>/`, outside all
  action sessions, and is maintained by a separate calibration workflow. Session staging does not
  copy source-session `raw_calibration/` files. Published session manifests and `metadata.jsonl`
  contain only explicit `device_ids.main`, `device_ids.left`, and `device_ids.right`; an unordered
  related-device list must not infer sides. Local paths, API payloads, and signed URLs are excluded.
- In `EgoMotionActions/PXX/<session_id>/`, the capture streams and motion-capture content are
  required. The concrete NOKOV export formats are optional choices and at least one format must be
  present. Only those format choices and explicitly selected RRD files are marked optional.
- ModelScope Web staging always uses the CLI compressed-video defaults. It does not expose raw-video,
  proxy-height, or CRF controls; the advanced video switches remain available in the CLI.
- ModelScope Web uploads require an existing repository. Repository creation, visibility, and license
  controls remain CLI-only.
- ModelScope Web scans RRD files in the selected Session/Segment and presents them as independent
  checkboxes. Only checked files are staged; an empty selection stages no RRD files. Re-staging
  synchronizes the generated session `rerun/` directory so previously selected files do not remain.

## ModelScope Publishing Proposal

The following is a proposal based on the ModelScope dataset documentation and is not yet a locked
project definition:

- Keep inspection reports directly accessible as standalone files even when the session data is
  additionally packaged as an archive.
- Add a ModelScope dataset-card `README.md` with YAML `configs`, schema, provenance, alignment
  definitions, known anomalies, license, and loading examples.
- Prefer ModelScope HTTP SDK/CLI upload with resumable cache over manually managing Git LFS for the
  initial large upload.
- Classify the ModelScope Dataset Card under the official `multi-modal` and `cv` domains and the
  `action-recognition` and `body-3d-keypoints` tasks. Keep egocentric video, motion capture, human
  motion, synchronization, and wearable IMU/MAG terms as searchable custom tags.

## Pending Decisions

- ModelScope namespace and English repository name.
- Public, private, internal, or gated access.
- Participant/privacy restrictions and any additional data-use terms beyond Apache License 2.0.
- Exact sessions and file variants included in the first release.
- The authoritative mapping from each recorded `<session_id>` to one `P01`-`P29` primitive. The
  workbook defines the action taxonomy and instructions but does not contain this session mapping.
- Whether the first release has train/validation/test splits or a single `data` split.
- Which inspection fields must be removed or converted before publication; local absolute paths must
  not appear in uploaded HTML reports.
- Whether compressed videos are preview media or canonical aligned media. The current packager
  explicitly resamples video to 30 FPS; this can change frame count and must be resolved before a
  frame-aligned dataset release.
